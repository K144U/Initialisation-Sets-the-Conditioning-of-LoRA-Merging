## 3. Infrastructure worth knowing

**Cluster.** `ssh sanjay.g@CLUSTER-HOST` (never the bare IP; it maps to a
student account where the project does not exist). Queue allows **2 running
jobs**. GPU pin set `1,2,3,4,6` — GPU 0 was held by another user at 78.9/81.9 GB
throughout; 5 and 7 are outside our allocation. Cluster code is byte-identical
to local (md5-verified); only its git bookkeeping is behind.

**The nll_tau cache is the reason the campaign finished in a day.** Each eval
cell runs 24 evaluations, 20 of which are the base model and task adapters
scored on each task and do not depend on the merge. Those are now cached per
`(base, cohort, loader)` in `results/phase3/nll_tau_cache/`. A cell went from
**57 minutes to about 10**. It was verified inert *before* use:
`check_nll_tau_determinism.py` found 8/8 cohort groups bitwise identical, 960
comparisons, worst difference exactly 0. The cache key includes the loader
because the two inference paths genuinely differ.

**Orchestrator.** One PBS job runs `orchestrator.py`, one worker per pinned GPU,
pulling from a manifest. Manifests are ordered so one cell per cohort comes
first, priming the cache before the rest hit it. Done markers make resubmission
resume rather than restart.

**Keeper.** `keeper_r6.sh` is the pattern: detached (`setsid`, ppid 1), polls
every 15 min, resubmits when the queue is empty and the manifest is unsatisfied,
capped at six resubmits. It exited cleanly on completion and never had to fire.

## 4. Gotchas that cost time, so they do not cost it twice

1. **`\PassOptionsToPackage{table}{xcolor}` must be the first line** of any
   build root. Both `tmlr.sty` and the ICLR style load eso-pic, which loads
   xcolor; without it `\cellcolor` is undefined and cells print `green!18`.
2. **`qsub -v GPUS=1,2,3,4,6` fails.** PBS splits the value on commas and reads
   the tail as further variable names: "cannot send environment with the job".
   Put the pin set in a file and pass `GPUS_FILE`.
3. **`pkill -f keeper_r6.sh` matches its own SSH command line** and kills the
   shell running it. Do not use it.
4. **`git commit -m "long message"` gets path-mangled** by MSYS on this box
   ("C:/Program Files/Git/ is outside repository"). Use `git commit -F -` with
   a heredoc. Same family as the known heredoc/backslash issue.
5. **`git clone` of this repo fails on Windows** because of a long filename in
   `SentEmail/`. Use `git clone --mirror` for tooling.
6. **BibTeX has no comment syntax between entries.** A comment ending
   "cited as @misc." made it skip the next entry and silently drop a reference.
7. Git identity must be forced: `git -c user.name=K144U -c
   user.email=95154157+K144U@users.noreply.github.com commit ...`.

## 5. The anonymised audit-trail bundle

`../rdmerge-audit-trail.bundle` (19 MB, outside the repo). Built by
`code/phase3/scripts/build_anon_bundle.sh`.

Why a bundle and not an anonymised repo link: the paper's central claim about
itself is that a reader can verify **commit ordering**. Snapshot anonymisers
(anonymous.4open.science and similar) serve files with no git history, which
removes exactly the thing being claimed. A bundle is one file carrying real
history; `git clone` works on it and `git merge-base --is-ancestor` runs.

The script removes correspondence, external review notes and author-named
drafts; rewrites identifying text across every blob and commit message;
rewrites author and committer identity; then **verifies no identifying string
survives in any blob in the object store** and refuses to write the bundle if
one does. The first pass leaked (`JIIT` x57, `pathak` x20, plus bibtex keys and
an unexpected email form) because the rules were case-sensitive; they are now
case-insensitive.

**If you rebuild the bundle, regenerate Table 6's hashes.** Anonymisation
changes every commit hash. It does not change topology, so the ordering claim
is unaffected, and the script prints the old-to-new mapping filtered to the
commits the table cites.
