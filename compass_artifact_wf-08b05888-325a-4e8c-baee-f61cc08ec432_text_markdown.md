# TurboQuant takes KV cache quantization to the Shannon limit

Google Research's TurboQuant is a **data-oblivious, online vector quantization algorithm** that compresses the key-value (KV) cache and nearest-neighbor search indices to within a small constant factor (roughly 2.7x) of the information-theoretic Shannon lower bound on distortion. It delivers roughly **6x KV-cache memory reduction and up to 8x decode speedup with zero accuracy loss at 3.5 bits per channel**, and does so without any calibration data, Hessian preprocessing, or per-block scale/zero-point metadata. The work is important not because it invents yet another low-bit trick, but because it closes the long-standing gap between practical vector quantizers and the provable Shannon distortion-rate bound, and it does so with a GPU-friendly, two-stage construction that can run entirely online during autoregressive decoding. One caveat up front that strongly shapes how you should read the result: TurboQuant is **not** a weights-only quantizer in the GPTQ/AWQ/QuIP lineage. It targets **activation-style vectors**, specifically the KV cache inside transformer attention and database vectors in ANN search. That framing is essential to understanding why it looks so different from the weight-quantization literature the user is familiar with.

## The problem TurboQuant actually solves

The paper, titled *TurboQuant: Online Vector Quantization with Near-optimal Distortion Rate* (arXiv:2504.19874, Zandieh, Daliri, Hadian, Mirrokni, accepted at ICLR 2026), poses vector quantization as a Shannon source-coding problem: design a map Q from R^d to {0,1}^(b·d) together with an inverse Q^(-1) that minimizes expected MSE distortion E[||x - Q^(-1)(Q(x))||²] and inner-product distortion E[|⟨y,x⟩ - ⟨y, Q^(-1)(Q(x))⟩|²] for worst-case inputs. In modern LLM serving this matters because **KV cache memory scales linearly with context length and dominates HBM footprint for long-context inference**, and because attention is fundamentally an inner-product operation, so quantizers that preserve dot products are what you actually need, not quantizers that merely minimize L2 reconstruction error.

Existing approaches all made unsatisfying trade-offs. Classical product quantization (PQ) and its variants (OPQ, IVFPQ, RabitQ) need an **offline k-means training phase per dataset**, which is incompatible with KV caches whose contents are generated token by token at inference time. Scalar approaches like **KIVI and KVQuant** use per-channel or per-token affine scalar quantization with float16 scale/zero-point metadata, which introduces "bit overhead": storing one fp16 scalar per block of 64 or 128 values costs an extra bit or two per coordinate and partially defeats the purpose at low bit-widths. Hessian-based methods (GPTQ, QuIP, QuIP#) depend on calibration data and second-order information, which you cannot recompute online for each new key or value vector. Grid-based data-oblivious methods such as the recent sphere-grid PQ are suboptimal in their distortion bounds and poorly vectorizable on GPUs. **What was missing was a quantizer that is simultaneously data-oblivious, online, accelerator-friendly, and provably near-optimal in distortion rate**, and that is precisely the gap TurboQuant closes.

## The algorithmic core, in full detail

TurboQuant's construction rests on a clean probabilistic observation. If you apply a **random orthogonal rotation R** to a unit-norm vector x in R^d, the distribution of each coordinate of Rx is exactly a symmetric **Beta((d-1)/2, (d-1)/2) distribution on [-1,1]**, which for large d concentrates like N(0, 1/d). More importantly, in high dimensions the d coordinates become **nearly independent** in a quantitatively strong sense, not merely uncorrelated. This independence is what lets you ignore joint structure across coordinates and just apply a one-dimensional scalar quantizer independently to each, while still achieving near-optimal *vector* distortion. This is the same "incoherence processing" trick QuIP and QuIP# use for weights, but applied to KV activations and exploited for a different end: rather than taming outliers, it reshapes the marginal distribution into a known analytic form so that an **optimal scalar codebook can be precomputed once**.

**Stage 1, TurboQuant_mse.** The authors precompute an optimal b-bit Lloyd-Max (Max-Lloyd) scalar quantizer for the Beta((d-1)/2, (d-1)/2) density by solving the continuous 1-D k-means problem on that density. Because this codebook is a function only of d and b, not of the data, it is baked in as a compile-time constant for useful pairs like d ∈ {128, 256} and b ∈ {2, 3, 4}. At inference time you rotate x, then map each coordinate to its nearest codebook entry and emit b bits, then unpack by a table lookup and inverse rotation. The rotation in practice is realized by a **random diagonal sign flip followed by a fast Walsh-Hadamard transform (FWHT)**, giving O(d log d) cost and no dense matmul, which is why it is accelerator friendly. The paper proves the rigorous distortion bound D_mse(Q_mse) ≤ (√3 · π / 2) · 4^(-b) for any unit-norm x, and gives concrete numbers at small bit-widths: roughly **0.36, 0.117, 0.03, 0.009 MSE at b = 1, 2, 3, 4** respectively. The unit-norm assumption is handled by storing the L2 norm of each vector in fp16, which is a negligible overhead of one scalar per d-dimensional vector.

**Stage 2, TurboQuant_prod.** The authors prove that any MSE-optimal quantizer is **biased as an inner-product estimator**, because the reconstruction error has a component correlated with the signal direction. If your application is attention scoring or ANN similarity, bias is worse than variance because it does not average out across tokens. Their fix is a **two-stage residual quantizer**: use b-1 bits for Q_mse to get a coarse reconstruction, compute the residual, then spend the remaining 1 bit applying a **Quantized Johnson-Lindenstrauss (QJL) transform** to the residual. QJL, from Zandieh et al.'s earlier work, multiplies the residual by a random Gaussian sketching matrix and keeps only the sign of each projection, yielding an unbiased 1-bit inner-product estimator. Composing these gives an unbiased estimator with distortion D_prod ≤ (√3 · π² · ||y||² / d) · 4^(-b), which is **exponentially tighter in b than prior 1-bit or low-bit online schemes** and matches the Shannon lower bound up to the ~2.7 constant the paper also proves.

**PolarQuant**, a companion paper accepted at AISTATS 2026 and described in the Google blog, is the further refinement TurboQuant actually composes with in the KV-cache pipeline. Instead of quantizing Cartesian coordinates directly, PolarQuant pairs up coordinates and maps each pair to polar (r, θ). The radii of multiple pairs are themselves grouped and polar-transformed recursively until the d-dimensional vector is distilled into a **single final radius and a collection of angles**. Because angles on a high-dimensional sphere have an even more concentrated distribution than raw coordinates, this recursive polar representation admits tighter scalar quantization per angle and eliminates the per-block normalization constant that cost prior methods their extra bits. The Google blog positions TurboQuant as a high-level system that uses **PolarQuant for Stage 1 compression and QJL for the 1-bit residual correction**, rather than the original Cartesian Lloyd-Max described in the arXiv v1.

## How this differs from the weight-quantization canon

For the user who works on LoRA merging and LLM evaluation, the cleanest mental model is this: **GPTQ, AWQ, SmoothQuant, QuIP, QuIP#, BitNet and OmniQuant all quantize weights (sometimes plus activations), offline, once per model**, using either Hessian information, activation-outlier rescaling, or quantization-aware training. TurboQuant does not compete with any of those. It quantizes the **KV cache and database embeddings, online, per vector, with zero training and zero calibration data**. You would in practice stack it on top of a weight-quantized model: keep your W4A16 GPTQ or AWQ weights, and use TurboQuant to shrink the KV cache from fp16 to roughly 3 to 3.5 bits per channel. The closest relatives in the literature are **KIVI, KVQuant, QuaRot's KV-cache path, QJL, and PolarQuant** itself, all of which live in the KV-cache niche. Among those, TurboQuant is distinguished by being the first to achieve provable near-Shannon-optimal distortion with **no per-block fp16 metadata**, which is exactly what limits how far the others can push below 4 bits.

The incoherence idea (random rotation to eliminate outlier structure) is the same algorithmic primitive that QuIP and QuIP# apply to weights, and it is worth noting that **QuaRot and SpinQuant** also use Hadamard rotations on activations for the same reason. TurboQuant's novel contribution over QuIP# is the **analytic exploitation of the Beta distribution** that rotation induces: QuIP# still learns codebooks via an E8 lattice and RTN, whereas TurboQuant derives the optimal codebook in closed form from a distribution it proves the data must follow post-rotation, which is what makes the whole pipeline data-oblivious and online.

## Empirical results and what they mean

The headline numbers reported in the blog and paper, validated by independent reimplementations on GitHub (the 0xSero/turboquant and spiritbuun forks), are the following. On **Llama-3.1-8B-Instruct and Ministral-7B-Instruct** across LongBench-E, RULER, ZeroSCROLLS, L-Eval, and Needle-In-A-Haystack, TurboQuant at a **4x KV-cache compression ratio matches full-precision generation quality up to 104k token contexts** with 100% needle retrieval. At **3.5 bits per channel it delivers absolute quality neutrality**, and at **2.5 bits per channel it shows only marginal degradation**, where the 2.5 and 3.5 figures come from a mixed-precision outlier treatment that allocates 3 bits to outlier channels and 2 bits to the rest. On LongBench-E the method outperforms token-eviction baselines (SnapKV, PyramidKV) and scalar KV quantizers without formal guarantees (KIVI). On **nearest-neighbor search benchmarks** it beats standard PQ and RabitQ on recall@k while reducing indexing time from seconds to **roughly 1.3 milliseconds for 1536-dim vectors** because there is no codebook to train. The paper also reports **up to 8x end-to-end decode speedup on H100** due to the combination of smaller KV memory footprint and fused compressed-attention Triton kernels that can operate directly on the packed 3-bit representation plus 1-bit QJL residual, avoiding full dequantization during the softmax inner-product phase.

The independent audit on GitHub is worth flagging because it sharpens some of the marketing claims. The third-party reimplementation confirms the **MSE numbers within 1% of the paper** (0.034 at 3 bits, 0.009 at 4 bits for d=128), and confirms that **at 3 bits per key with 2 bits per value the cosine similarity of reconstructed attention outputs is around 0.94**, which is where quality begins to degrade on harder tasks. The effective compression ratio after counting the rotation matrices Π and S and the ring buffer is closer to 4.6x at 4k context and approaches 5x at 32k, not the 6x quoted in marketing copy, because the rotation matrices amortize over long contexts but not short ones. Recall at top-1 with 3-bit quantization on arbitrary query-key pairs is only about 38%, but attention-weighted recall on the dominant-mass tokens is essentially perfect, which is why downstream LLM quality is preserved even though raw vector recall looks mediocre.

## Practical implications for deployment

The practical story breaks into four parts. First, for **edge deployment**, 3-bit KV compression is what finally makes 32k to 100k-token contexts feasible on phones and laptops with 8 to 16 GB of unified memory, because for long-context inference the KV cache rather than the weights is the binding memory constraint. The MLX community had a working TurboQuant implementation within hours of the Google blog post, and the llama.cpp project has an active integration discussion (#20969) with CPU and CUDA kernels already validated. Second, for **inference cost**, the compression compounds with weight quantization: a 4-bit weight model plus 3-bit KV cache with TurboQuant gives you roughly 4x weight compression and 5x to 6x KV compression simultaneously, which translates directly into larger batch sizes at the same HBM budget and therefore lower $/token. Third, for **memory bandwidth**, the reduction in bytes moved from HBM to SRAM per decode step is the actual source of the 8x speedup, because decode is memory-bandwidth-bound; the method shines most on long contexts where KV reads dominate. Fourth, for **kernel considerations**, the design is deliberately friendly to Tensor Cores and Triton: the FWHT rotation is a log-linear butterfly that vectorizes cleanly, the per-coordinate codebook lookup is a small constant-memory table, and the fused compressed-attention kernel can precompute Q·centroid partial scores to eliminate the lookup from the inner loop entirely. Pre-generating the rotation matrices Π and S rather than rebuilding them per layer is the recommended pattern, because the overhead of one fp16 norm scalar per vector is negligible.

## Limits, caveats, and what remains open

Several things TurboQuant does **not** do are worth stating explicitly. It **does not quantize weights**, so you still need GPTQ, AWQ, or similar for the weight matrices; it is complementary rather than substitutive. It **does not help with training memory** at all, only inference KV cache and ANN index memory, which is why the TechCrunch framing about "RAM shortages" for AI training is misleading. It **assumes the post-rotation Beta distribution**, which is exact only under a truly random rotation; in practice the FWHT-based pseudo-random rotation is a good enough approximation for d=128 and above but degrades for very low dimensions. The **2-bit-value regime is the quality bottleneck**: the independent benchmarks show cos_sim around 0.94 for 2-bit values versus 0.997 for 4-bit values, so for quality-sensitive workloads the sweet spot is 3 bits for keys and 4 bits for values, not the marketing-friendly 2-bit headline. The **unbiasedness of TurboQuant_prod is an expectation over the QJL randomness**, so variance can still be nontrivial on short contexts where the JL concentration has not kicked in. Finally, the 2.7x gap from the Shannon lower bound, while small, is not zero, and the independent commentary on turboquant.net argues persuasively that **KV-cache compression is approaching an information-theoretic wall**: each further bit of savings costs disproportionately more engineering effort, and the next major gains will come from rethinking attention itself (linear attention, state-space models, hybrid architectures) rather than from squeezing vector quantization further.

## Paper, authors, and landscape context

The formal citation is **Amir Zandieh, Majid Daliri, Majid Hadian, and Vahab Mirrokni, "TurboQuant: Online Vector Quantization with Near-optimal Distortion Rate," arXiv:2504.19874, April 28, 2025, accepted at ICLR 2026**. Zandieh and Mirrokni are at Google Research, Hadian at Google DeepMind, and Daliri at NYU (he is the corresponding author for the arXiv submission and was the lead theorist on the related QJL paper from 2024). Vahab Mirrokni leads the Google Research algorithms team and has a long track record on sketching, hashing, and large-scale optimization, which is the algorithmic heritage TurboQuant draws on. The companion works are **QJL (Zandieh, Daliri, Han, 2024)** for the 1-bit residual sketch and **PolarQuant** at AISTATS 2026 for the polar-coordinate refinement. There is no official Google-released code repository at the time of writing, but two high-quality third-party implementations exist: **0xSero/turboquant** (vLLM integration, Triton kernels, paper-matching MSE) and **spiritbuun/llama-cpp-turboquant-cuda** (llama.cpp CUDA fork with a norm-correction tweak that makes 3-bit TurboQuant beat q8_0 perplexity), and an active llama.cpp mainline integration discussion at ggml-org/llama.cpp#20969.

In the broader **2025-2026 LLM quantization landscape**, TurboQuant represents the maturation of the "KV-cache quantization" subfield into something with the same theoretical grounding that weight quantization gained from GPTQ and QuIP a few years earlier. The field now has three reasonably distinct pillars: **weight quantization** (GPTQ, AWQ, QuIP#, QuaRot, SpinQuant at 2 to 4 bits), **activation quantization** (SmoothQuant, OmniQuant, FP8/FP4 formats in NVIDIA Blackwell and Hopper), and **KV-cache quantization** (KIVI, KVQuant, QJL, TurboQuant, PolarQuant). TurboQuant effectively closes the theoretical question in the third pillar by matching the Shannon bound within a constant, which is why the independent analysts on turboquant.net are correct to frame this as **a boundary result rather than just another paper**: further gains in raw KV compression are now bounded by information theory, and the research frontier is shifting toward architectural alternatives to attention, adaptive precision allocation based on attention scores, and combining KV compression with aggressive token eviction. For a researcher working on LoRA merging and evaluation, the immediate practical implication is that **long-context evaluation harnesses can now run at 3 to 4x larger batch sizes on the same hardware**, and that any evaluation you do of LoRA adapters on long-context tasks should probably fix the KV quantization scheme as a controlled variable, because at 2.5 bits per channel it starts to interact measurably with downstream task accuracy even if perplexity looks clean.

## Conclusion

TurboQuant is less a new quantization trick and more a **principled, information-theoretically optimal framing of KV-cache compression** that happens to also be fast on GPUs. Its central insight is that a random rotation turns an arbitrary vector into one with analytically known Beta-distributed coordinates, which lets you precompute the optimal scalar quantizer once and run it online forever, and that a 1-bit QJL sketch on the residual fixes the inner-product bias that pure MSE quantizers suffer from. The practical payoff is 6x smaller KV caches and up to 8x faster decode with no measurable quality loss at 3.5 bits per channel, and the theoretical payoff is a 2.7x-from-Shannon bound that effectively tells the community where the ceiling is. The next research moves will be combining TurboQuant with outlier-aware mixed precision (to push into the 2-bit regime cleanly), fusing it deeper into attention kernels on Blackwell and MI350 class hardware, and exploring whether the same rotation-plus-Beta-plus-Lloyd-Max recipe transfers usefully to weight and activation quantization, where the distributional assumptions are harder to justify but the algorithmic template may still buy something. For deployment today, the recommendation is straightforward: pair your existing 4-bit weight quantizer with TurboQuant at 3 to 4 bits per KV channel, budget one fp16 norm scalar per vector, and expect the long-context inference economics of your stack to change materially.
